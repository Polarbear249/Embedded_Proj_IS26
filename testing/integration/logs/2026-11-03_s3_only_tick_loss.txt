Finding 1 (measured): S3-U01 FAIL, 200 ms tk_dly_tsk read 331087 us on
TIMERAWL, while the line task's seq advanced only 19 cycles (19-20 = 200 ms
of KERNEL time). Clocks are configured right (PLL 125 MHz for SysTick,
12 MHz / 12 = 1 MHz TIMER, kernel/sysdepend/pico_rp2040/cpu_clock.c), so
kernel ticks were lost during the window.
First guess (WRONG): the PR #6 telemetry printing (tm_printf masks
interrupts per call). Rerun 2 with printing switched off read 331240 us,
the same. Change reverted.
Current hypothesis (not proven): the window is the first thing after boot
and overlaps cyw43_init() (WiFi firmware download), which holds core 0;
earlier IMU logs show one ~132 ms gap at start-up too (per max 131952 us),
while steady-state IMU periods are 9-11 ms. Test: image
s3_only_settle_smp1_usb_cdc_wifi_test.uf2 (APP_TEST_SETTLE_MS 5000, tests
start 5 s after boot). PASS there = start-up only, not a running problem.
WIFI=none build not possible: subsystem1 needs cyw43_utk.h.

Finding 2: S3-U06 readings never changed for the whole window:
C=1 R=0 BC=0 mode=1 on every line. CONFIRM with the tester whether black was
moved under each sensor. If it was: the inputs do not follow the sensors
(check each module's LED, the comparator pot, sensor height, Grove 5/6/7).
